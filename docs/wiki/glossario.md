# Glossario

| Termine | Significato |
|---|---|
| **BAD** | Business Application Developer: il team che fa Power Platform (Power Apps, Power Automate, Power BI) |
| **BID** | Business Intelligence Software Developer: il team che fa DB, API e interfacce web |
| **SAL** | Stato Avanzamento Lavori: incontro di verifica intermedio con il cliente |
| **KPI** | Key Performance Indicator: indicatore chiave per misurare il successo dell'evento |
| **ETL** | Extract, Transform, Load: leggere i dati grezzi, pulirli, caricarli nel DB |
| **Modello dati condiviso** | Il DB PostgreSQL usato sia da BID sia da BAD |
| **Vista SQL** | Query salvata nel DB che si interroga come una tabella; la usiamo per i KPI |
| **Contratto API** | Specifica degli endpoint (OpenAPI) concordata prima di scrivere il codice |
| **OpenAPI** | Formato standard per descrivere una REST API |
| **ADR** | Architecture Decision Record: file breve che registra una decisione e il suo perché |
| **Padiglione** | P1 Console & PC, P2 Esports & Community, P3 Indie, Retro & Cosplay |
| **Varco / tornello** | Punto di ingresso a un padiglione dove si legge il biglietto |
| **Stand** | Spazio espositivo identificato da un codice (es. `P1-A01`) |
| **Planimetria** | Elenco degli stand con padiglione, mq, posizione |
| **Listino** | Prezzi di spazi ed extra per l'edizione |
| **Acconto / saldo** | Le due rate di pagamento di un contratto |
| **Prelazione** | Diritto dell'espositore a riprenotare lo stesso stand nell'edizione successiva |
| **Imponibile** | Importo del contratto al netto dell'IVA |
| **Lead / contatto** | Visitatore che lascia i propri dati a uno stand |
| **Saturazione** | Quota di spazio espositivo venduto rispetto a quello disponibile |
